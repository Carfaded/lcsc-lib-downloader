## 本版修复

### 3D 模型下载增加两级自动回退

**问题现象**：某些编号在立创商城页面能看到 3D 模型，工具却提示
「无关联EDA器件(无3D模型)」或「3D模型信息查询失败」。

**根因**：工具原先只走立创专业版的器件链路
`商品搜索 → hasDevice → 3D Model 属性 → 模型资源查询`，
这条链路在部分器件上数据缺失（器件未关联 EDA 器件），
或立创给器件**换了编号**（旧编号搜不到当前商品）时就会中断。

**修复**：专业版仍作主路径，失败后自动回退两级——

1. **编号被更换** → 用搜索到的同型号新编号继续
   （仅在数字部分完全相等时才采纳，避免 `C8299` 误配到 `C82993` 这类风险）
2. **标准版封装资源** → 封装数据里的 `SVGNODE` 记录含 3D 资源编号，
   与专业版的 `dataStr.model` 是**同一个值**，直连 CDN 取到的就是同一份 STEP

两条都不通时，错误信息会明确写明
「专业版未找到该编号的商品; 标准版回退失败(元件库未找到)」，不再笼统报错。

### 实测结果

| 编号 | 修复前 | 修复后 |
|---|---|---|
| C7174 | ✗ 3D模型信息查询失败 | ✓ 正常下载（1.06 MB，几何校验通过） |
| C97787 | ✗ 未找到该编号的商品 | ✓ 正常下载（2.65 MB，几何校验通过） |
| C82993 | ✗ 未找到该编号的商品 | ⚠ 明确提示「元件库未找到」（该编号确已下架） |
| 正常器件 | ✓ | ✓ 主路径无退化 |

> 回退过程在日志里可见，例如：
> `· 专业版链路不可用(3D模型信息查询失败)，改用标准版 3D 资源`

## 完整功能

| 功能 | 说明 |
|---|---|
| 3D 模型 (STEP) | 纯元器件不含 PCB，自动几何校验，**两级自动回退** |
| 原理图符号 | 立创EDA 标准格式 JSON |
| PCB 封装 | 立创EDA 标准格式 JSON |
| AD 符号库 (.SchLib) | AD 原生二进制，可选内嵌 3D |
| AD 封装库 (.PcbLib) | AD 原生二进制，可选内嵌 3D |
| 多器件合并 | 整批合并为 `LCSC3D.SchLib` / `LCSC3D.PcbLib`（封装去重） |
| 手动合并 | 已有多个 `.SchLib`/`.PcbLib` 手动合并为一个 |
| 运行日志 | 一键清空，每轮下载自动清空 |
| 批量下载 | 界面粘贴 / codes.txt / 命令行，自动去重 |
| 风控重试 | 请求间隔 + 指数退避，断连自动恢复 |
| 免安装 | 单文件 exe，无需 Python |

## 下载

**Windows 用户**：下载 `lcsc-lib-downloader-v1.2.1.exe`，双击即用。
**无需安装 Python**，无需任何运行库。

> 首次运行如被杀毒软件提示（PyInstaller 打包程序常见误报），添加信任即可。

## 使用

### 图形界面
1. 粘贴立创编号（一行一个）
2. 选择保存路径
3. 勾选需要的内容
4. 点击「开始下载」

### 命令行
```bash
python lcsc_3d_downloader.py C131443 C25804          # 全量
python lcsc_3d_downloader.py -f codes.txt -o D:\step  # 从文件读
python lcsc_3d_downloader.py C131443 --types ad        # 只生成 AD 库
python lcsc_3d_downloader.py -f codes.txt --merge --types ad   # 合并为单库
```

### AD 中使用
- `File → Open` 打开 `.SchLib` / `.PcbLib`
- 或 `Components 面板 → 菜单 → File-based Libraries Preferences → Add Library`
- 查看 3D：打开 `.PcbLib` 后按快捷键 `3`

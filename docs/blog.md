# 我造了一个立创商城元件库下载器：3D 模型、原理图符号、PCB 封装和 AD 原生库，一键拿下

> 一个免安装的小工具，输入立创编号（C131443 这种），自动下载 4 类文件：
> 3D 模型 STEP、立创EDA 原理图符号、PCB 封装，以及最难的——**Altium Designer 原生库（SchLib / PcbLib，3D 模型直接内嵌）**。
> 本文记录这个工具从找数据接口一路做到二进制格式生成的完整技术过程，包括走过的弯路。

## 一、缘起：一个真实的小痛点

画板子的人对下面这套流程一定不陌生：

在立创商城找到一个器件 → 需要它的 3D 模型做机械装配检查 → 需要符号和封装画原理图、画 PCB。

立创其实提供了这些数据，但下载体验一言难尽：

- 3D 模型要从立创EDA 专业版里逐个"导出"；
- 立创EDA 专业版的 **PCB 编辑器导出 3D 会连带一整块 PCB 基板**（很多人在这里踩坑）；
- 想要 AD（Altium Designer）能用的库？官方导出的是整张图纸，还得在 AD 里再"提取库文件"；
- 想批量搞几十个器件？纯手工点到手酸。

于是有了这个项目：**输入编号，四种文件一次拿到，全程自动化，带图形界面，打包成一个双击即用的 exe。**

## 二、技术拆解

### 2.1 第一关：数据从哪来

立创有两套 API，各有各的用处，我在工具里用了两条链路：

**① 3D 模型（专业版链路）**

```
POST pro.lceda.cn/api/eda/product/search        # 按 C 编号搜索商品 → 拿到 hasDevice
POST pro.lceda.cn/api/devices/searchByIds       # 查器件属性 → attributes["3D Model"]
POST pro.lceda.cn/api/components/searchByIds    # 查 3D 模型资源 → dataStr.model
GET  modules.lceda.cn/qAxj6KHrDKw4blvCG8QJPs7Y/{model}   # 下载 STEP
```

**② 符号/封装（标准版链路）**

```
GET  lceda.cn/api/products/{编号}/components
     → result.dataStr              # 原理图符号（明文 JSON）
     → result.packageDetail.dataStr # PCB 封装（明文 JSON）
```

标准版接口返回的是 EasyEDA 的经典明文格式（`shape` 数组里是 `R~`/`E~`/`PAD~`/`TRACK~` 这类记录），可以直接在立创EDA里导入。

**风控是真实存在的。** 实测发现：

- 短时间连续请求会被服务器直接断连（RemoteDisconnected）；
- `curl` 能过的请求，裸 Python `urllib` 会被断——必须带上完整的浏览器请求头（`Origin`、`Referer`、`Accept-Language` 等全套）；
- 请求间隔要 ≥1 秒，失败后要指数退避重试。

所以工具里内置了**退避重试 + 请求间隔控制**，被风控断连会自动恢复，批量下载不受影响。

### 2.2 第二关：怎么保证 STEP 模型"不含 PCB"

要求很明确：3D 模型必须是**纯元器件**，不能带 PCB 基板。怎么自动验证？

最初的想法很简单：解析 STEP 里所有坐标点，算包围盒。尺寸合理就是纯元件——**然后就翻车了**。

以 0603 电容（C14663）为例，算出包围盒宽 4mm，而 0603 的本体应该只有 1.6mm。排查发现：STEP 里**倒圆角的圆弧，圆心放在模型外很远处**（X=±2mm），圆弧本身却很小——用"所有坐标点"统计，圆心就把包围盒撑大了。

**正确姿势**：只统计被 `EDGE_CURVE` 引用的 `VERTEX_POINT`（即实体真实的边端点），得到的就是实体真实尺寸：

| 器件 | 顶点法尺寸 | 判定 |
| --- | --- | --- |
| C131443 (LQFP-64) | 12.01 × 12.01 × 1.45 mm | ✓ 引脚跨距 12mm 吻合 |
| C25804 (0603) | 0.81 × 1.62 × 0.45 mm | ✓ |
| C14663 (0603) | 1.60 × 0.80 × 0.80 mm | ✓ |

再叠加对 `pcb`/`board`/`substrate` 等关键词的全文扫描，双保险。

> 另一个关键结论：**立创EDA 专业版"元件库"里的 3D 模型本身就是纯元件**，不含基板；含基板的是"PCB 编辑器导出 3D"那条路。所以走对数据源，问题就解决了一半。

### 2.3 第三关：AD 原生库——最硬的一块骨头

这是整个项目最费周折的部分。

**目标**：生成 Altium Designer 能直接打开的原生 `.SchLib` / `.PcbLib`，而不是"文字描述"或需要再转换的中间格式。

#### 弯路：逆向官方导出引擎

用户提示"立创EDA 自己就能导出 AD 格式"，于是我顺着这条线挖了下去，而且挖得很深：

1. 找到了立创官方导出 AD 时实际使用的转换引擎——**chameleon**（一个 5MB 的浏览器扩展包，解开来是个 7.5MB 的 Node.js 程序）；
2. 发现它**可以直接命令行运行**，还带 HTTP 服务模式（`POST /conversion`），支持 12 种输入格式 × 多种输出格式，其中就有 `altium`；
3. 摸清了它的请求协议，成功用它把器件数据转成了官方同款的 ASCII 格式 `.schdoc`/`.pcbdoc`；
4. 结果发现：**纯文件转换走不到终点**。官方导出带着"编辑器上下文"（元件实例的放置信息），纯数据只能生成缺元件框架的"裸图元图纸"，在 AD 里提取不出完整的库。

能跑通 90% 却发现最后一步是个死胡同——这就是逆向工程的日常。

#### 正路：站在 LCSC3D 的肩膀上

转去寻找现成方案，找到了开源项目 [LCSC3D](https://github.com/Travelerrrrrr/LCSC3D)——有人已经用 Python 完整实现了"立创数据 → AD 原生二进制库"的转换链，并且**逐字段对照过官方导出**验证。

我的工作变成了：**把它的核心转换模块裁剪出来，嵌进这个小工具**。核心链路只有十几个模块：

```
输入（立创 JSON）
  → easyeda_import  解析 '~' 记录 → 中间表示(IR)
  → altium_ir       IR → AD 记录（坐标换算：1 EDA单位 = 10mil = 100000 AD原始单位）
  → altium / compound_storage
                    记录封装 + 用 Windows 原生 OLE 组件写出 CFB 复合文档
  → .SchLib / .PcbLib（AD 原生二进制）
```

生成的库用独立解析器（olefile 反向读取）验证：

- C131443 → SchLib：**64 个引脚**（编号 1~64）+ PcbLib：**64 个焊盘** + 206 个丝印图元，焊盘 0.30×1.5mm 与 LQFP-64 吻合；
- 0603 电阻/电容 → 各 2 引脚 / 2 焊盘。

#### 攻坚：把 3D 模型内嵌进 PcbLib

LCSC3D 的 PcbLib 支持**把 3D 模型直接内嵌进封装库**（AD 里按 `3` 就能看到立体模型），这是它最香的功能。这部分也啃了下来：

1. **模型资源**：封装数据里的 `SVGNODE` 记录藏着模型编号，用它可以下载成对的资源：
   - STEP（建模用）：`modules.lceda.cn/qAxj6KHrDKw4blvCG8QJPs7Y/{uuid}`
   - OBJ（用作放置基准）：`modules.lceda.cn/3dmodel/{uuid}`
2. **放置参数**：AD 里模型要放对位置，需要知道"模型原点在哪"。妙就妙在——**官方放置用的是 OBJ 的几何基准**（X/Y 包围盒中心 + 最低点），不是 STEP 自身原点。所以两个文件都得下载，用 OBJ 顶点算出基准，再用旋转矩阵推导出最终偏移。
3. **写入格式**：STEP 用 zlib 压缩后存入 AD 的 `Library/Models/*` 流；同时在封装里写一条"3D 主体（BODY）"记录（含旋转角、高度偏移、校验和等 20 多个参数）。

验证方式简单粗暴但有效：**把生成的 PcbLib 里的内嵌数据解压出来，和官方源 STEP 逐字节比对**——

```
STEP 源文件: 12610101 bytes | 内嵌解压: 12610101 bytes   ✓ 完全一致
```

换 0603 电阻再测一遍也通过。至此，"AD 库 + 内嵌 3D"完整落地。

### 2.4 验证：怎么证明"真的能用"

工具类项目最怕"看起来能用"。这个项目里我采用了三层验证：

1. **独立解析器反向校验**——用第三方读取器（olefile）解析生成的文件，核对引脚数、焊盘数、内嵌数据完整性，而不是只检查"文件生成了"；
2. **逐字节比对**——内嵌 3D 与官方源文件必须 bit 级一致；
3. **洁净环境自测**——exe 打包内置了 `--selftest` 模式，在"最小 PATH + 清空所有 PYTHON 环境变量"的环境下真实下载+转换+校验，确保在没有 Python 的电脑上照样工作。

另外通过 PE 依赖分析确认：exe 只依赖 5 个 Windows 系统 DLL，运行时自带解压的 Python 运行时，**目标电脑什么都不用装**。

## 三、成品长什么样

- **图形界面**：粘贴编号 → 选路径 → 勾选四类内容 → 开始下载；实时日志显示每一步（含风控重试、模型校验结果）；
- **命令行**：`python lcsc_3d_downloader.py C131443 C25804 --types ad`，纯标准库无依赖；
- **合并库**：多器件一键合并为单个 `LCSC3D.SchLib` / `LCSC3D.PcbLib`（相同封装自动去重，符号引用自动指向最终封装名）——几十个器件也只有一个库文件，随用随加；
- **输出示例**（C131443）：

```
C131443_LQFP-64(10x10).step                    12.6 MB   纯元件 3D 模型
C131443_GD32F303RCT6.symbol.json               14 KB     原理图符号(立创格式)
C131443_LQFP-64_..._LS12.0-BL.footprint.json   98 KB     PCB封装(立创格式)
C131443_GD32F303RCT6.SchLib                    31 KB     AD 符号库(64引脚)
C131443_LQFP-64_...-BL.PcbLib                  2.2 MB    AD 封装库(64焊盘+内嵌3D)
```

## 五、写在最后

这个项目技术上最有意思的点在于：**真正的难点从来不是"下载"**，而是：

1. 判断下载到的数据**是不是你要的东西**（不含 PCB 的几何校验）；
2. 输出到目标软件能**直接用**的格式（AD 二进制库 + 3D 内嵌）；
3. 对结果做**可验证的证明**（独立解析、逐字节比对、洁净环境自测）。
